Selected work

Projects & Practical Labs

Open each project for its workflow, key tasks, technical details, and security lessons. All security testing should remain within authorized environments.

Designed a simulated small-enterprise network in Cisco Packet Tracer, organizing endpoints into logical departmental VLANs and planning IPv4 addressing for each subnet. Configured switch access ports and 802.1Q trunks, enabled inter-VLAN routing with router subinterfaces, and set up DHCP addressing where appropriate. Verified the topology using commands such as show vlan brief, show interfaces trunk, and show ip route, followed by connectivity tests between hosts. The project demonstrates network segmentation, routing fundamentals, configuration validation, and structured troubleshooting.

Key tasks

  • Built a topology using routers, switches, and end devices.
  • Planned subnetting and assigned IP addresses and default gateways.
  • Configured VLANs, trunk links, and inter-VLAN communication.
  • Tested reachability and used CLI output to troubleshoot issues.

Security relevance

Segmentation can reduce unnecessary communication between departments and provides a foundation for applying access-control rules. A next step would be to document ACL requirements and test permitted versus blocked traffic.

Completed practice in the authorized TryHackMe Airplane room environment, following a methodical penetration-testing workflow rather than relying on a single tool. Started with host discovery and Nmap port/service enumeration, then reviewed exposed services and gathered evidence to identify possible attack paths. The Linux-focused investigation included checking file permissions, SUID-enabled binaries, and privilege-escalation opportunities. Notes were organized around the observation, validation steps, potential impact, and defensive recommendations.

Methodology

  • Reconnaissance and port/service enumeration with Nmap.
  • Follow-up enumeration based on discovered services.
  • Review of Linux users, permissions, and potentially risky binaries.
  • Validation of findings in the training lab and documentation of the attack path.

Deliverables and learning

A repeatable lab walkthrough/report structure, evidence-based observations, and remediation ideas such as reducing exposed services, applying least privilege, and reviewing risky file permissions. This is a training-room exercise, not a claim of testing a real organization.

Used OWASP Juice Shop, an intentionally vulnerable web application, as a safe environment to practice web security testing. Explored application routes and request/response behavior, inspected authentication-related flows, and used browser developer tools and Burp Suite concepts to understand how user-controlled input reaches the application. The assessment focused on selected OWASP Top 10 themes, recording test conditions and evidence before considering the likely impact and practical remediation.

Assessment activities

  • Mapped application functionality and interesting endpoints.
  • Inspected HTTP requests, parameters, responses, and session behavior.
  • Practiced identifying and safely validating common web vulnerability patterns in the lab.
  • Recorded reproducible steps, risk context, and remediation suggestions.

Security outcomes

Built familiarity with manual web testing and communicating findings clearly. Recommended defensive themes include server-side input validation, parameterized database queries, secure session handling, least-privilege authorization checks, and regression testing after fixes.
